# Module 02 — Group Formation and Instance Setup

## Brief Overview

A brief logistics module. Attendees self-organise into groups of 5, receive shared RHDP credentials for their pre-provisioned demo instance, nominate a starting driver, and verify login access before the live walkthrough begins. The instructor sets expectations for how the group dynamic works during the session.

## Audience and Time

- **Roles:** Red Hat Solution Architects, Technical Sales Specialists — intermediate
- **Prerequisites for this module:** Module 01 complete
- **Duration:** 10 minutes (hard cap — the walkthrough must start on time)

## Learning Objectives

- Access the shared RHDP demo instance as a group using the provided credentials
- Confirm the instance is healthy and ready before the live walkthrough begins

## Steps

1. Instructor announces the group size (max 5 per group) and asks attendees to self-organise. Groups can form naturally with neighbours — there is no assignment logic.
2. Instructor or event staff distribute group credentials (one printed or shared sheet per group). Each sheet contains:
   - OpenShift console URL and login
   - GitLab URL and login
   - Showroom URL (this enablement lab content)
3. Each group nominates a starting driver — the person who will have the keyboard first. Any group member can nominate themselves; the group decides. The driver role can rotate at any point during the session.
4. Driver opens the OpenShift console and confirms login. Group members observe on the driver's screen (laptop screen share to a group monitor, or simply gathering around one laptop).
5. Driver confirms GitLab login.
6. Instructor does a quick show-of-hands: "Who is not logged in yet?" — resolves any access issues before moving on.

## Instructor Notes

- Keep this module to 10 minutes. If access issues affect more than one or two groups, proceed anyway and let those groups pair with a working neighbour temporarily — troubleshooting live in a room of 100 consumes disproportionate time.
- If a group's instance failed to provision, direct them to share with the nearest group. Two groups of ~10 is a valid fallback — observers are still learning.
- The driver rotation expectation is important to set here: there is no rule about when to rotate. Groups can swap after each section, after a natural pause in the demo, or whenever they choose. The point is that everyone knows it is an option.
- For virtual delivery: distribute credentials in a DM or private Slack message to one person per breakout room; that person shares their screen in the room.

## Infrastructure Notes

- 20 instances are pre-provisioned by the RHDP team before the session. Credentials are prepared and distributed by the event organiser.
- The facilitator should have one spare credential set available in case a group's instance fails to provision or is unreachable.
